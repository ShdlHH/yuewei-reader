01功能分析（现状）

本节结论全部来自 0.7.19 桌面端代码与真机操作验证，不含推测。目的：先明确「现在有什么、缺什么、哪里不好用」，再据此定迭代范围。

1.1 产品定位与信息架构

定位：不依赖网页、可自建书源的 Windows 小说阅读器，支持在线抓取阅读、本地 TXT 导入、整本下载离线、WebDAV 跨设备同步进度与书架。

阅读页工具条（← 书架 / 书名 / 目录 / Aa）+ 目录侧栏（可拖宽）+ 正文区 + 页眉页脚（章名、页码、阅读百分比）整章预分页后逐页翻，非滚动阅读；上一章 / 下一章按钮只存在于 Aa 面板内

1.3 关键链路

链路 A · 找书到开始读 搜索关键词 → 多源并行抓取 → 结果按书名+作者聚合 → 选来源 → 加入书架 → 书架点开 → 拉取目录 → 加载首章 → 阅读
链路 B · 长期阅读 打开书 → 恢复上次章节与章内位置 → 逐页翻 → 章末进下一章（已预取则直出）→ 退出时保存进度 → 启动/手动同步
链路 C · 离线化 书架右键「全部下载」或下载页新建任务（全部/未缓存/区间）→ 队列抓取 → 失败章节集中重试 → 离线阅读
链路 D · 书源维护 导入 Legado JSON → 列表校验 → 失败时进入分阶段调试（搜索/详情/目录/正文）→ 修正或删除

02业务需求拆解

2.1 业务需求

原始需求 「功能更加好用、更加完整」——在不改变「本地优先、自建书源、轻量无广告」定位的前提下，降低高频操作的成本，让用户能把它当作主力阅读器连续使用。

据此给出两条业务目标（均为可观察结果，不设虚构量化指标）：

目标可观察结果
G-1 操作更省力切章、下载后开始读、进入沉浸阅读都不超过一步；不用打开设置面板去找入口
G-2 异常有出路、使用有反馈任一失败场景给出人话原因与下一步动作；阅读量与追更状态在应用内可见

04功能需求（P0）

每条统一说明：目的 → 入口与触发 → 处理规则 → 结果与状态 → 异常与边界。共享口径统一见第 06 节，不重复。

FR-01失败可恢复：错误分级与就地动作 P0

解决 P-01：现在只显示一段带原始异常的错误文字，用户无法自我恢复。

入口与触发
覆盖三个场景：阅读页章节加载失败、搜索页某书源失败、同步失败。
处理规则
  • 错误统一分级为四类，按类别给动作（技术细节收进「详情」折叠区，默认收起）：
    ① 网络不可达 / 超时 → 「重试」「检查网络设置」
    ② 书源规则失效（解析为空 / 结构不匹配）→ 「换用其它来源」「去校验书源」
    ③ 章节不存在或地址缺失 → 「更新目录」「先下载本书」
    ④ 书源被删除 / 书籍被删除 → 「查看书籍信息」「重新添加书源」
  • 「换用其它来源」：仅当该书在书架中记录了多个来源时可用，列出其它来源及其章节数供选择；切换后保留当前阅读位置的百分比。
  • 「重试」必须复用当前章节位置，不重置阅读进度。
结果与状态
  • 阅读页失败态：正文区居中展示「原因一句话 + 动作按钮 + 详情折叠」。重试成功后原位恢复正文，不闪回加载占位。
  • 搜索页：失败书源在右侧进度列表中以「失败 · 原因类别」展示，并提供单源「重试」。
  • 同步失败：侧栏同步卡显示「同步失败 · 类别」，点击展开详情与「重试同步」。
异常与边界
  • 同一章连续失败 3 次：提示「可能规则已失效」并直接给出「去校验书源」。
  • 离线状态：网络类动作改为「已离线，恢复网络后重试」，不反复弹出报错。
  • 用户取消操作：回到失败态，不清除已缓存内容。

FR-02新章节检测与更新提醒 P0

解决 P-02：追更的书更新了，用户完全不知道。

入口与触发
  • 手动：书架 ⋯ 菜单「更新目录」（已有）保留。
  • 自动：应用启动后与每 [TBD：默认 60 分钟，可关闭] 一次，对书架中的在线书检查目录新增章节；仅在应用打开且距上次检查超过间隔时执行，不常驻后台。
处理规则
  • 一次检查只请求目录页，不抓正文；按书串行，遵守请求间隔设置。
  • 新增章节数 > 0 时记录「有更新」并缓存新增章名；用户读到新章节后清除标记。
  • 单轮最多检查 [TBD：20 本]，其余下一轮继续。
  • 检查失败不改变「有更新」状态，也不打断阅读。
结果与状态
  • 书目行显示「更新 N 章」标记；「继续阅读」卡片在无在读进度时优先展示有更新的书。
  • ⋯ 菜单与「继续阅读」卡片提供「读最新章」：更新目录后直接跳到最新章并提示「已是最新」。
  • 设置页新增「更新检查」开关与间隔（关闭 / 30 分钟 / 60 分钟 / 手动）。
异常与边界
  • 书源失效：书中标记「来源失效」，不进入自动更新队列，直到用户处理。
  • 目录长度缩短（源站删章）：不删本地已缓存章节，仅提示「目录变化」。
  • 离线：只做本地检查，不影响可读性。

FR-03阅读页章节导航与目录定位 P0

解决 P-03：上一个/下一个章节按钮藏在 Aa 设置对话框中，切章要多开一层。

入口与触发
  • 阅读页工具条新增「‹ 上一章」与「下一章 ›」，紧随「← 书架」之后，始终可见。
  • 目录侧栏新增「定位到当前章」按钮；打开目录时若列表未停在当前章，显示提示条「已跳到第 N 章位置」。
  • Aa 面板内的上一章 / 下一章按钮保留（不影响既有习惯）。
处理规则
  • 工具条切章行为与键盘 PageUp/PageDown 一致：往后落在新章开头，往前落在上一章结尾。
  • 首章时「上一章」置灰，末章时「下一章」置灰，并悬停提示「已是第一章 / 最后一章」。
  • 切换过程中防抖：同一章在 350ms 内不重复触发（与现有翻章节奏一致）。
结果与状态
  • 点击后章名、页码、百分比即时刷新；已缓存或已预取的章节直接显示正文。
  • 目录中当前章始终高亮；「定位到当前章」把列表滚动到当前章并选中。
异常与边界
  • 章节加载失败：保持工具条可用，正文区进入 FR-01 的失败态。
  • 目录尚未加载完成：两个按钮置灰并提示「目录加载中」。
  • 快速连点：只响应最后一次，不产生越界跳转。

FR-04沉浸式阅读与自定义快捷键 P0

解决 P-04：没有全屏/沉浸模式，快捷键固定，长时间阅读干扰多。

入口与触发
  • F11 或双击正文空白处进入 / 退出全屏；退出用 Esc。
  • 工具条新增「沉浸」按钮（图标），点击后隐藏左侧目录侧栏、页眉页脚与工具条，仅保留正文与右下角页码。
  • 设置页新增「快捷键」区：翻页（下一页 / 上一页）、切章（下一章 / 上一章）、目录、阅读设置、沉浸模式共 7 项可改键。
处理规则
  • 沉浸模式：鼠标移入屏幕顶部 60px 或按 Esc 临时唤出工具条；3 秒无操作再次隐藏。
  • 全屏与沉浸可叠加：全屏只影响窗口，沉浸影响页面元素；退出沉浸不影响全屏状态。
  • 改键：点击后按下新组合键即生效；与已占用组合冲突时提示「该组合已用于 xx」，允许覆盖或取消。
  • 快捷键只在本应用窗口内生效；焦点在输入框时不拦截。
  • 提供「恢复默认快捷键」。
结果与状态
  • 进入沉浸：正文版心随窗口自适应，页码与百分比保留在右下角；阅读位置不变、不触发重新分页跳页。
  • 快捷键修改立即保存，重启后保持；设置页显示当前组合与「默认值」对照。
异常与边界
  • 全屏被系统占用/失败：回退为「最大化 + 隐藏框架」，并提示一次。
  • 目录侧栏原本是关闭状态：退出沉浸后恢复进入前的显隐状态。
  • 用户把「下一页」绑定到与「下一章」相同的键：阻止保存并说明冲突。

FR-05下载任务直达阅读 P0

解决 P-05：下载完成后任务表没有阅读入口，只能回书架找书。

入口与触发
  • 下载任务表双击任意行 → 打开该书的阅读页。
  • 任务表右键菜单与工具条新增「阅读」按钮（未选中任务时置灰）。
  • 任务完成时在状态栏提示中加入「打开」动作链接。
处理规则
  • 打开位置：若该书有阅读进度则恢复到进度位置；无进度则从第 1 章开始。
  • 区间下载任务：优先定位到该任务的起始章节。
  • 书籍已被移出书架：提示「该书已不在书架」，提供「重新加入」或忽略。
结果与状态
  • 打开后下载队列照常运行，互不阻塞；返回下载页时任务状态与进度为最新。
异常与边界
  • 任务下载中且该书章节未缓存：允许打开，未缓存章节按现有逻辑加载（失败则进入 FR-01 失败态）。
  • 书籍只存在于下载记录但已被删除：行置灰并标注「书籍已删除」。

06共享规则

6.1 阅读进度口径

进度 = 章节序号 + 章内百分比（0–10000 的整数）。工具条切章、键盘切章、下载任务打开、换源跳转都必须复用同一口径；章内百分比只在分页完成后计算，避免不同排版下取整不一致。

6.2 缓存与预取

章节正文按「书 + 章」缓存；已缓存章节切章直出，未缓存章节预取下一章。新增的「读最新章」「下载任务打开」优先命中缓存，未缓存部分沿用现有加载与失败处理。

6.3 错误提示分级

类别用户可见文案（示例）默认动作是否折叠技术详情
网络网络连接失败，请检查网络后重试重试是
书源规则该书源解析不到正文，可能规则已失效换来源 / 校验书源是
内容缺失这一章在源站不存在或地址已变更更新目录 / 先下载是
数据被删书源或书籍已被删除查看信息 / 重新添加是

6.4 同步范围与冲突

同步对象：阅读进度、书架条目、更新标记。合并键保持「书名 + 作者」；同一对象更新时间较新者生效，被覆盖一方保留为副本并在同步结果中计数，不静默丢弃。快捷键与沉浸偏好属于本机设置，不参与同步。

6.5 请求克制

任何自动行为（更新检查、预取、下载）都必须遵守设置中的并发数与请求间隔；自动行为失败不得弹出模态框打断阅读，只做状态栏提示。

6.6 布局与入口一致性

新增入口（工具条切章、沉浸按钮、下载阅读）一律沿用现有工具条样式与位置规则；不新增悬浮球、不做隐藏手势；所有图标按钮必须带悬停提示与键盘可达性。
