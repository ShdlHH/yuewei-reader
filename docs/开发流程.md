## 二、阶段 0：同类项目调研结论

### 参考项目

| 项目 | 形态 / 技术 | 与本项目的关系 | 可借鉴点 |
|---|---|---|---|
| [gedoor/legado（开源阅读）](https://github.com/gedoor/legado) | Android / Kotlin | 书源规则的事实标准 | 书源 JSON 字段体系、搜索/详情/目录/正文四段解析模型、书源校验思路 |
| [aooiuu/any-reader](https://github.com/aooiuu/any-reader) | Electron / TypeScript 多端 | 书源 + 本地 TXT/EPUB 双模式的直接对标 | 规则解析库与 UI 分离（core / legado / rule-utils）、规则调试、本地书导入 |
| [uncle-novel/uncle-novel](https://github.com/uncle-novel/uncle-novel) | Java + JavaFX + MyBatis + SQLite | 同技术栈的桌面端先例 | 书架/分组、本地 TXT 导入、下载管理、书源管理、全局热键、主题 |
| [LibreraReader](https://github.com/foobnix/LibreraReader) | Android / Java | 多格式阅读器的工程结构 | TXT/Markdown 转单 HTML 文档再渲染、阅读器分页与排版设置 |
| [koodo-reader](https://github.com/koodo-reader/koodo-reader) | Electron / React | 纯本地多格式阅读 | 书库目录扫描、阅读进度与书架信息组织 |
| [LNReader](https://github.com/LNReader/lnreader) | Android / React Native | 插件式源管理 | 源的安装/更新/启停模型，源失效时的降级策略 |

参考文档：
- [Legado 入门文档](https://gedoor.github.io/docs/GettingStarted)
- [Legado 书源编写指南](https://nendozen.github.io/legado-source-guide/)
- [AnyReader 规则说明](https://aooiuu.github.io/any-reader/rule/)

### 结论

1. **规则格式不做自研**：直接对齐 Legado 3.0，用户可复用社区书源，避免从零积累规则生态。
2. **功能骨架参考 uncle-novel**：同为 JavaFX + SQLite 桌面端，书架、下载、书源管理的模块划分可直接借鉴。
3. **规则引擎分层参考 any-reader**：规则解析与界面解耦，独立成库，便于单元测试和后续扩展；但 P0 不追求全量兼容（不支持 JS 规则与登录态）。
4. **本地 TXT 参考 Librera**：先把文件转成统一章节模型，再交给同一阅读器渲染，不为本地/在线写两套阅读界面。

## 四、阶段 2：技术方案与架构

### 4.1 技术栈

| 层面 | 选型 | 说明 |
|---|---|---|
| 运行时 | Java 21（LTS） | 虚拟线程处理并发抓取，无需引入复杂线程池 |
| UI | JavaFX 21 + FXML + CSS | 与 uncle-novel 同路线；`Platform.runLater` 更新界面 |
| 构建 | Gradle + `org.openjfx.javafxplugin` | 便于模块化与打包 |
| 存储 | SQLite（`sqlite-jdbc`）+ 本地文件目录 | 结构化数据入库，章节正文落文件，避免库膨胀 |
| HTML 解析 | Jsoup | 规则引擎选择器基础 |
| JSON | Jackson | 书源 JSON 读写与详情接口解析 |
| JSONPath | Jayway JsonPath | 支持 JSON API 类型书源 |
| 网络 | JDK `HttpClient` | 内置、异步、支持超时与并发控制 |
| 打包 | `jpackage`（可选 jlink） | 生成 exe/msi 与便携包 |
| 测试 | JUnit 5 + MockWebServer | 规则引擎用固定 HTML 样本回归 |

### 4.2 分层结构

```
reader/
├── app/                     # 启动、路由、依赖装配
├── ui/                      # JavaFX 视图与控制器（书架/阅读器/书源/下载/设置）
├── application/             # 用例编排（导入书籍、搜索、下载、校验书源）
├── domain/                  # 领域模型与规则（Book/Chapter/BookSource/Progress/DownloadTask）
└── infrastructure/
    ├── persistence/         # SQLite DAO、迁移脚本
    ├── network/             # HTTP 客户端、限流、重试、UA
    ├── rule/                # 规则引擎（解析、执行、调试输出）
    ├── txt/                 # 编码识别、分章、正文清洗
    └── cache/               # 章节正文文件缓存
```

依赖方向：`ui → application → domain`，基础设施由 application 通过接口调用；domain 不依赖 JavaFX 与数据库实现。

### 4.3 规则引擎设计要点

- **规则 DSL**：按 `@` 切分为有序步骤；步骤类型包含 `class` / `tag` / `id` / `text` / `href` / `src` / `regex` / `jsonpath` 等；每步支持下标（`.0` 表示第一个）。
- **四段管线**：`search → bookInfo → toc → content`，每段输出统一的中间结果（书籍摘要、书籍详情、章节列表、正文文本）。
- **上下文变量**：`{{key}}`、`{{page}}` 在 URL 层替换；相对链接按“当前页面地址 → 书源地址”顺序补全。
- **失败定位**：每段记录 `阶段 / 请求 URL / 状态码 / 耗时 / 匹配数量 / 首个空字段`，直接供调试面板与校验结果使用。
- **兼容性标记**：遇到 JS 规则、登录配置时置为「部分支持」，不抛异常中断导入。
- **可测试性**：引擎输入 = 规则 + HTML 字符串，输出 = 结构化结果，完全不依赖 UI 与网络，便于用样本集做回归。

### 4.4 数据模型（概要）

| 表 | 关键字段 |
|---|---|
| `book_source` | id、name、url、group、type、enabled、status、last_check、rule_json、created_at |
| `book` | id、title、author、cover、intro、source_type、source_id、book_url、chapter_count、last_read_at |
| `chapter` | id、book_id、index、title、content_state、word_count、content_path |
| `reading_progress` | book_id、chapter_index、char_offset、updated_at |
| `download_task` | id、book_id、range_type、state、success_count、fail_count、failed_chapters |
| `setting` | key、value |

正文缓存目录按 `bookId/chapterIndex.txt` 存放；清理缓存只删文件并把章节状态回退为未缓存，不改阅读进度。

### 4.5 关键接口约定

- `BookSourceEngine`：`search(source, keyword, page)`、`fetchDetail(source, bookUrl)`、`fetchToc(source, bookUrl, tocUrl)`、`fetchContent(source, chapterUrl)`、`validate(source, keyword)`。
- `ChapterCache`：`read(bookId, index)`、`write(bookId, index, text)`、`remove(bookId)`。
- `DownloadService`：`createTask(bookId, range)`、`pause(taskId)`、`resume(taskId)`、`cancel(taskId)`、`retryFailed(taskId)`。
- 所有网络调用统一经过 `HttpGateway`（超时、重试、并发、UA、离线检测）。

## 七、阶段 5：测试策略

| 层级 | 范围 | 做法 |
|---|---|---|
| 单元测试 | 分章规则、编码识别、正文清洗、规则 DSL 各步骤、URL 补全、去重 | JUnit 5，规则引擎使用固定 HTML 样本（含正常/改版/空结果三类） |
| 集成测试 | 搜索→详情→目录→正文链路、下载状态机、缓存读写 | MockWebServer 模拟站点，覆盖超时、403、空页面、结构变化 |
| 数据测试 | 导入/删除/重复导入/书源删除后的书籍状态 | 临时 SQLite 文件，验证约束与级联行为 |
| 界面冒烟 | 四条主流程、空态、错误态、快捷键 | 手工用例表；关键路径可加 TestFX |
| 回归样本集 | 每适配一个真实书源，保存其 HTML 快照与期望结果 | 防止规则引擎改动导致旧源失效 |

P0 验收口径（与 PRD 目标对应）：
1. 导入 TXT → 得到可跳转目录 → 任意章节可读 → 重启后回到原位置。
2. 导入书源 → 校验通过 → 搜索到书 → 加入书架 → 读到正文。
3. 书源规则改坏后，调试面板能指出失败环节。
4. 下载整本 → 断网 → 已缓存章节可读，未缓存章节给出明确提示。

## 八、阶段 6：构建与发布

实际工程采用 Maven（非 Gradle），发布流程如下：

```powershell
# 1. 测试与打包（产出含全部依赖的 fat jar）
mvn test
mvn -DskipTests package

# 2. 准备 jpackage 输入目录（只放一个主 jar）
#    target\package-input\yuewei-reader.jar

# 3. 生成免安装应用目录（内置精简 JRE）
jpackage --type app-image --name 阅微阅读器 --app-version 0.2.0 --vendor 阅微 `
  --input target\package-input --main-jar yuewei-reader.jar `
  --main-class com.yuewei.reader.Launcher --icon packaging\app.ico --dest dist

# 4. 生成 Windows exe 安装包（需要 WiX Toolset 3 的 candle.exe / light.exe 在 PATH 中）
jpackage --type exe --name 阅微阅读器 --app-version 0.2.0 --vendor 阅微 `
  --input target\package-input --main-jar yuewei-reader.jar `
  --main-class com.yuewei.reader.Launcher --icon packaging\app.ico --dest dist `
  --java-options "-Dfile.encoding=UTF-8" `
  --win-shortcut --win-menu --win-menu-group 阅微 --win-dir-chooser --win-per-user-install
```

- 图标：`src/main/resources/icon/app-*.png` 用于窗口/任务栏；`packaging/app.ico` 用于安装包与快捷方式。
- 产物：`dist\阅微阅读器\`（免安装目录）、`dist\阅微阅读器-0.2.0.exe`（安装包）。
- 版本号与数据库迁移脚本绑定；升级时自动迁移，失败则备份原库并提示，不静默丢数据。
- 发布物清单：安装包、免安装目录、使用说明（如何导入书源/TXT、如何校验书源）、更新日志。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 站点改版导致书源大面积失效 | 在线阅读不可用 | 调试面板定位失败环节；规则引擎做回归样本；明确提示换源 |
| Legado JS 规则书源占比高 | 兼容率低于预期 | P0 明确标注“部分支持”；按第 6 节结论决定是否二期支持 |
| 规则引擎复杂度失控 | 工期与稳定性 | 先只实现四段管线与常用动作，用真实书源驱动，不做全字段覆盖 |
| 大文件 TXT 解析卡顿 | 首屏体验差 | 后台解析 + 进度提示；必要时流式分章 |
| 抓取频率引发站点限制 | 请求被封 | 并发上限、同站点限 2 并发、可配置间隔、失败退避 |
| 合规与内容风险 | 产品不可分发 | 不内置书源与内容、首次启动免责声明、数据仅本地 |
