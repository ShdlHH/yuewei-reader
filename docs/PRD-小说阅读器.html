阅微 · 小说阅读器

一个把「网络书源」和「本地 TXT」放进同一个书架的 Windows 桌面客户端：导入书源即可在线找书，导入 TXT 即可离线阅读，下载过的章节断网也能继续看。

01背景与目标

追更的人同时面对两种割裂的阅读方式：网页端广告多、排版乱、进度记不住；本地 TXT 没有目录、换设备要重新找位置；而现成的阅读工具往往只解决其中一半——要么只能读本地文件，要么只做在线书源。

产品要做的判断是：本地书和网络书在同一个书架里，用同一个阅读器读完。因此书籍、章节、阅读进度必须是一套统一模型，来源只是书籍的一个属性，而不是两套系统。

目标（以可观察的结果表述）

  • 导入一份本地 TXT 后，用户能直接看到可跳转的章节目录，并从任意章节开始阅读。
  • 导入一份 Legado 书源 JSON 后，用户能在同一界面完成「搜索 → 查看详情 → 加入书架 → 阅读正文」。
  • 对任意一本在线书发起下载后，已缓存章节在断网状态下仍能打开。
  • 书源失效时，用户能定位到失败环节（搜索 / 详情 / 目录 / 正文）并自行修正规则，而不是只看到“加载失败”。
产品边界前置声明：本软件不内置、不分发任何书源与书籍内容，仅提供规则解析与本地文件阅读能力；所有书源由用户自行导入，所有阅读数据只保存在本机。

02范围与优先级

首版以「一位用户在自己电脑上，从导入到读完一章」为最小闭环。下列 P0 项全部参与这个闭环；P1 项在闭环稳定后追加。

优先级能力为什么在这个优先级
P0本地 TXT 导入与自动分章无需网络即可验证「书架 → 目录 → 阅读 → 记进度」整条链路
P0书架与阅读器产品主体，所有来源的内容都在这里被消费
P0Legado 3.0 书源导入决定在线阅读能覆盖多少站点，是核心差异点
P0在线搜索、详情、目录与正文书源价值必须在完整解析链路上体现
P0书源管理（增删改、启停、校验、调试）书源会失效，没有调试能力用户无法自救
P0批量下载与离线缓存“断网可读”是在线阅读的兜底，也是 P0 明确要求
P1换源（同一本书切换书源继续读）提升追更成功率，但不阻塞首版闭环
P1书架分组、排序自定义、封面自定义书多之后的整理需求
P1EPUB 导入、听书（TTS）格式与场景扩展
P1数据备份 / 恢复、WebDAV 同步换机与多设备场景
不做内置书源市场、内置书籍内容、账号体系、云同步、移动端涉及内容分发的合规风险，或与桌面单机定位不符
Legado 兼容性的明确边界（P0 只做到这里）：支持 ruleSearch / ruleBookInfo / ruleToc / ruleContent 四段网页规则，以及 class / tag / id / text / href / src 等常用规则动作、{{key}} / {{page}} 变量与正则替换；不支持规则内嵌 JavaScript、需要登录态的站点、音频/图片类书源（bookSourceType ≠ 0）。这类书源允许导入，但会被标记为「部分支持」并说明原因。

03产品模型与主流程

核心对象

对象定义关键属性来源差异
书源 一份描述“如何从某个站点取数”的规则集合 名称、站点地址、分组、启用状态、健康状态、最近校验时间、原始规则 JSON 仅在线书使用；同一份 JSON 可含多个书源
书籍 书架上的一个条目，是阅读进度的归属对象 书名、作者、封面、简介、来源类型（本地 TXT / 书源）、所属书源、书籍地址、章节数、最近阅读时间 本地书无书源与书籍地址；在线书必须有所属书源
章节 书籍内可独立定位、独立加载的阅读单元 序号、标题、正文状态（未缓存 / 缓存中 / 已缓存 / 失败）、字数 本地章节来自 TXT 解析；在线章节来自目录规则 + 正文规则
阅读进度 用户在某本书中的停留位置 章节序号、章节内字符偏移、最后阅读时间 两类书籍共用同一套进度结构
下载任务 一次批量缓存章节的执行记录 范围（全部 / 未缓存 / 指定区间）、状态、成功数与失败数、失败章节清单 仅在线书产生

主流程 A · 本地 TXT 阅读

STEP 1选择或拖入文件书架入口或窗口拖拽
STEP 2识别编码与分章自动识别 + 可选规则
STEP 3确认书名与目录预览前几章，可改名
STEP 4入架并阅读从第一章或上次位置进入

主流程 B · 书源在线阅读

STEP 1导入书源JSON 文件 / 粘贴内容
STEP 2校验书源跑通四段解析链路
STEP 3关键词搜索按书名聚合多源结果
STEP 4详情与目录补全信息、拉取章节
STEP 5加入书架写入统一书籍模型

主流程 C · 下载后离线阅读

STEP 1发起下载全部 / 未缓存 / 区间
STEP 2排队执行可暂停、继续、取消
STEP 3完成并标记书架显示已离线
STEP 4断网阅读缓存命中直接打开
统一规则：无论来源如何，一本“已加入书架”的书都必须具备书名、至少一个章节、可保存的阅读进度。缺少任一项的内容不算入架成功，不允许只把搜索结果直接塞进书架。

04功能需求

每个模块按「目的 → 入口 → 处理规则 → 结果与状态 → 异常」组织。跨模块复用的规则统一写在第 5 节，模块内只引用、不重复定义。

FR-01

本地 TXT 导入与自动分章

P0 · 入口模块

目的：让没有书源的用户也能在导入后立刻得到可跳转的目录，而不是拿到一个几百页的纯文本块。

入口
书架空状态按钮「导入本地 TXT」、书架工具栏、窗口拖拽文件
触发条件
用户选择一个或多个 .txt 文件

处理规则

  • 编码识别：依次尝试 UTF-8（含 BOM）→ UTF-16（含 BOM）→ GB18030；仍失败则不自动入架，弹出编码手动选择（UTF-8 / GBK / GB18030 / UTF-16），重新解码后继续。
  • 分章：使用内置章节目录规则识别标题行，至少覆盖「第 X 章 / 第 X 节 / 第 X 卷 / 序章 / 楔子 / 番外 / Chapter N」等常见写法；识别结果需满足“标题行数量 ≥ 2 且按顺序递增”，否则视为分章失败。
  • 分章失败的处理：提供三个可选项——按固定字数切分、整本作为单章、手动切换/输入章节规则。用户选定后重新解析，不改动原始文件。
  • 书名：默认取文件名（去扩展名），允许在确认页修改；作者默认「未知」，允许修改。
  • 重复导入：以文件内容指纹判断。已存在同一文件时提示「已在书架」，不建立第二条记录，用户可主动选择“仍然导入为新书”。
  • 大文件：超过 [TBD] 的 TXT 改为后台解析，并在书架显示解析进度；解析期间该书不可阅读。

结果与状态

  • 生成 1 本本地书籍 + N 条章节记录，原文保存到本地书库目录；书籍状态由「解析中」变为「可阅读」。
  • 导入完成后停留在书架，新书置于列表首位并高亮；用户也可直接进入阅读。

异常

场景处理
空文件 / 非文本二进制拒绝导入，提示“文件内容为空或不是文本”，不做任何写入
编码无法识别保留弹窗，允许手动选择编码或取消导入
分章结果为 0 或仅 1 章进入分章失败处理，不静默按整本入架
解析中用户关闭窗口中断解析，不产生半成品书籍记录
文件被外部删除或移动库内已有正文副本，阅读不受影响；仅在用户执行“重新解析”时提示源文件不存在

目的：作为所有书籍的唯一入口，让用户一眼看出“哪些能离线读、哪些来自书源、上次读到哪”。

书架线框：左侧全局导航，顶部搜索/筛选/排序，主区为封面网格

处理规则

  • 展示：封面（缺失时用书名首字生成占位）、书名、来源标签（本地 / 在线）、阅读状态（未读 / 已读至第 N 章 / 已离线）。
  • 排序：最近阅读、加入时间、书名；默认最近阅读优先，未读新书排在已读书之后。
  • 筛选：全部 / 本地 / 在线；与书架内搜索框叠加生效，搜索范围仅限书名与作者。
  • 打开：单击选中，双击或回车进入阅读；有阅读进度则回到上次位置，否则从第一章开始。
  • 右键菜单：书籍详情、继续阅读、更新目录（仅在线）、下载（仅在线）、移除。
  • 移除：弹出确认，并让用户勾选“同时删除已下载章节 / 本地正文副本”；默认不勾选。移除只影响本地数据，不改动用户原始 TXT 文件。

异常

  • 书架为空：展示引导，两个入口分别是「导入本地 TXT」与「先在书源页导入书源」。
  • 在线书所属书源被删除：该书保留在书架，标记「书源已移除」，只能阅读已缓存章节。
  • 封面加载失败：回退到占位图，不显示破图。
FR-03

阅读器

P0 · 核心体验

目的：用同一套阅读界面承载本地与在线内容，并稳定记住读到哪里。

布局

活着 · 第 3 章
第 1 章 家
第 2 章 失去
第 3 章 归途
第 4 章 老牛
第 5 章 余晖
第 3 章 归途
42%空格 / ← → 翻页18:24

阅读器线框：可收起的目录侧栏 + 正文区 + 底部进度与快捷键提示

处理规则

  • 目录：显示全部章节，当前章高亮；支持按章节名搜索；目录可收起，收起状态跨会话记忆。
  • 正文显示：在线章节先做标签剥离与空白规整，段落首行缩进；正文中的广告行按共享规则过滤；不渲染远程图片（P0 只读文字）。
  • 翻页：空格 / PageDown 下一页，PageUp 上一页，方向键按行滚动；到章节边界自动进入下一章或上一章；滚动模式下到底部后再继续滚动触发下一章。
  • 阅读设置：字号、行距、字体、页宽、主题（纸白 / 米黄 / 夜间），即时生效并全局保存。
  • 进度保存：记录章节序号与章节内字符偏移；在切换章节、关闭阅读器、窗口失焦、应用退出时保存。
  • 在线章节加载：打开章节时优先用已缓存内容；未缓存则请求书源正文规则，成功后写入缓存并更新章节状态；同时预取下一章。
  • 更新目录：打开在线书时对比目录，新增章节以角标提示「有 N 章更新」，用户确认后合并，不打断当前阅读位置。

异常

场景处理
正文请求失败（网络 / 规则）正文区显示失败原因与「重试」；连续失败 3 次后提示“可尝试切换书源或检查规则”，不自动跳章
解析出的正文为空视为失败并提示“该书源正文规则可能已失效”，不写入空缓存
正文异常超长超过 [TBD] 字符时截断展示并提示，防止单章撑爆内存
离线且章节未缓存提示“本章尚未下载”，提供“连接网络后重试”；目录中该章标记未缓存
进度位置失效章节数变少或偏移越界时，回退到最近的合法章节开头，并提示一次
FR-04

书源导入

P0 · 在线能力入口

目的：让用户能把社区已有的 Legado 书源直接搬进来用，而不是被迫手写规则。

入口
书源管理页「导入书源」、拖拽 .json 文件、粘贴 JSON 文本
支持格式
单个书源对象；书源数组；一次选择多个文件

处理规则

  • 字段映射：读取 bookSourceName、bookSourceUrl、bookSourceGroup、bookSourceType、bookSourceComment、enabled、searchUrl 及四段规则对象。
  • 必填校验：bookSourceName 与 bookSourceUrl 缺失的对象跳过，计入失败并给出原因。
  • 类型处理：bookSourceType ≠ 0（音频 / 图片等）允许入库，但状态直接标为「不支持」，默认不启用，不参与搜索。
  • 兼容性检查：规则值中出现 JavaScript 规则标记或依赖登录的配置时，标记「部分支持」，并在详情中列出不支持的字段。
  • 去重：以 bookSourceUrl 判定重复。默认跳过已存在项；导入结果页提供“覆盖同名地址书源”选项，选择后保留用户原有的启用状态与分组。
  • 分组：bookSourceGroup 中以分号分隔的多分组拆分为多个标签。
  • 导入后：默认不立即校验，由用户手动触发；导入结果页提供「全部校验」按钮。

结果与状态

导入结束后展示汇总：成功 N 个、跳过 M 个、失败 K 个；失败与跳过项逐条列出名称、地址与原因。新书源状态为「未校验」。

异常

  • JSON 语法错误：整体导入失败，提示首个错误所在行，不写入任何数据。
  • 顶层不是对象也不是数组：提示“不是有效的书源文件”。
  • 数组内部分对象非法：合法项照常导入，非法项计入失败，不做整体回滚。
  • 文件编码非 UTF-8：按 FR-01 的编码识别顺序处理。
FR-05

在线搜索

P0 · 找书

目的：一次关键词输入，就能看到多个书源里能读到的候选书，并知道每本来自哪个源。

入口
左侧导航「搜索」、书架顶部搜索框（切换为全网搜索时）
前置条件
至少有一个「已启用且校验正常」的书源

处理规则

  • 搜索范围：默认全部可用书源；用户可切换为按分组或指定单个书源。
  • 执行方式：各书源并行请求，单源超时 [TBD] 秒；并发上限在设置中可调。
  • 结果聚合：以「书名 + 作者」归并同一本书，卡片默认展示一个来源，展开后列出全部可用书源及其最新章节。
  • 排序：书名完全匹配优先，其次按来源可用数量降序，再按结果原始顺序。
  • 分页：书源 searchUrl 含 {{page}} 时支持「加载更多」；不支持分页的源只展示首屏。
  • 加入书架：必须先拉取书籍详情并成功获取目录，才允许入架；入架后按钮变为「已在书架」，点击跳转该书详情。

结果与状态

搜索过程按书源展示进度（搜索中 / 已完成 N 条 / 失败）。全部结束后，顶部汇总“N 个书源返回结果，M 个失败”，失败源可展开查看原因。

异常

场景处理
关键词为空或仅空白不发起请求，提示输入书名或作者
没有可用书源展示引导，跳转书源管理页导入
单源超时 / 解析为空该源标记失败并记录原因，不影响其他源结果
全部源失败显示“全部书源搜索失败”，按失败环节归类（搜索规则 / 网络 / 站点变更）
加入书架时目录为空阻止入架，提示“目录为空，可尝试其他书源或检查目录规则”
FR-06

书籍详情

P0 · 决策与入架

目的：在入架前让用户确认这本书是不是要找的，并能看到来源与更新情况。

展示内容

封面、书名、作者、分类标签、简介、最新章节、来源书源名称、目录章节数。未加入书架时底部按钮为「加入书架」；已加入时为「开始阅读」。

处理规则

  • 详情信息按「搜索结果已有字段 → 详情页规则补全」顺序合并，详情页解析到的同名字段覆盖搜索结果。
  • 简介过长时折叠，点击展开；保留换行。
  • 刷新信息（仅在线书）：重新执行详情与目录规则，更新简介、最新章节与章节列表；不改变阅读进度。
  • 本地书同样有详情页，展示书名、作者、章节数、文件来源与缓存占用，不显示书源相关操作。

异常

  • 详情页请求失败：展示搜索结果中已有的信息，简介区显示获取失败与「重试」。
  • 目录获取失败：禁止入架，提示可切换其他来源或稍后重试。
  • 封面地址无效：使用占位图。
FR-07

书源管理：列表、校验与调试

P0 · 可维护性

目的：书源会随站点改版失效。用户必须能自己判断“哪个源坏了、坏在哪一步、怎么改”。

列表

列说明
名称 / 地址名称可点击进入详情；地址作为副标题截断展示
分组多标签展示，可据此筛选
状态未校验 / 校验中 / 正常 / 异常 / 部分支持 / 不支持
最近校验时间 + 失败环节（搜索 / 详情 / 目录 / 正文）
启用开关，关闭后不参与搜索

操作

  • 新建（空白模板）、编辑规则 JSON、删除、导入、导出（单个或全部为 Legado 兼容 JSON）、批量启用/停用、按分组筛选与名称搜索。
  • 删除：二次确认，提示受影响书架书籍数量；删除后这些书只保留已缓存章节。
  • 编辑：内置 JSON 编辑器提供语法高亮与格式校验；保存前检查必填字段与 URL 合法性；保存后状态回到「未校验」。
  • 校验：使用用户指定的测试关键词（默认取上一次搜索词）依次执行 搜索 → 详情 → 目录 → 正文，逐段记录耗时与结果；任一段失败即判为异常，并保留其余段的执行结果。

异常

  • 校验中：该书源不可编辑、不可删除，可取消校验。
  • 规则 JSON 非法：保存被阻止，定位到错误位置。
  • 站点返回 403 / 需要登录：判为失败，提示“站点可能限制访问或需要登录，当前版本不支持登录态”。
  • 删除书源后：受影响书籍标记「书源已移除」。
FR-08

下载与离线缓存

P0 · 离线兜底

目的：把在线内容变成本地可读内容，让追更和断网场景都不依赖实时请求。

入口
书籍详情页「下载」、书架右键「下载」、下载管理页
范围选项
全部章节 / 仅未缓存章节 / 指定区间（起始章 - 结束章）

处理规则

  • 队列：同一本书同一时间只允许一个活动任务；多本书的任务按创建顺序排队。
  • 并发与间隔：并发数默认 2，可在设置中调整；每次请求之间保留可配置间隔，避免给站点造成压力。
  • 增量：“仅未缓存”只抓取状态为未缓存或失败的章节；已缓存章节跳过。
  • 暂停 / 继续 / 取消：暂停后已完成的章节保留，继续时从断点续传；取消保留已完成内容，任务标记已取消。
  • 失败重试：单章失败自动重试，仍失败则记入失败清单；任务结束后可「重试失败章节」。
  • 完成：全部成功时标记该书「已离线」，书架展示离线标识，并发送应用内完成提示。

状态机

排队中→ 下载中⇄ 已暂停→ 已完成 /部分失败 /已取消
当前状态允许操作迁移条件
排队中取消轮到执行→下载中；用户取消→已取消
下载中暂停 / 取消全部成功→已完成；存在失败→部分失败
已暂停继续 / 取消继续→下载中
部分失败重试失败章节 / 取消重试成功→已完成
已完成 / 已取消重新发起新任务—

离线阅读与磁盘

  • 章节打开优先级：本地缓存 → 在线请求 → 失败提示。
  • 设置页与书籍详情展示缓存占用；支持清理单本缓存（清理后未下载章节恢复为未缓存，阅读进度保留）。
  • 缓存总占用超过用户设定上限时，提示清理，不自动删除任何书籍内容。

异常

  • 下载中断网：任务转为已暂停并说明原因，网络恢复后不自动继续，需用户确认。
  • 书源在任务执行中被删除或停用：暂停任务并提示，已下载内容保留。
  • 磁盘空间不足：暂停任务并提示所需空间。

设置与本地数据

P0 · 支撑

目的：把会影响阅读与抓取行为的参数集中在一处，并让用户知道自己数据存在哪里。

05共享规则与异常

以下规则被多个模块引用，只在此处定义一次。

5.1 规则解析与失败判定

规则内容
规则执行顺序按 @ 分段从左到右依次收窄范围；每段在前一段结果集内执行，前一段为空即整体为空。
相对地址解析出的链接若为相对路径，以当前页面地址为基准转为绝对地址；无当前页面地址时以书源地址为基准。
字段失败单个字段解析为空不中断整条链路，但「书名」为空视为该书无效；「目录」为 0 章视为目录失败；「正文」为空视为正文失败。
校验判定搜索有结果 → 详情可取书名 → 目录 ≥ 1 章 → 任取一章正文非空，四段全过才判定为「正常」；否则记录首个失败环节。
部分支持命中不支持的规则能力（JS 规则、登录态）时状态为「部分支持」，默认不参与搜索，用户可手动启用并承担失败风险。

5.2 正文清洗

  • 剥离 HTML 标签与脚本样式，保留段落换行；连续空行压缩为一个。
  • 去除整行重复的站点推广语、广告行、字数统计行；过滤规则内置，不在界面暴露。
  • 全角空格与不可见字符统一处理；段落首行缩进两个字符由阅读器渲染时添加，不改写缓存原文。
  • 清洗后的正文写入缓存，原文不保留；若清洗后为空，则按正文失败处理。

5.3 命名、去重与删除

场景规则
书源去重以规范化后的 bookSourceUrl（去尾斜杠、统一小写主机名）为唯一判定依据。
书籍去重本地书用文件内容指纹；在线书用「书源 + 书籍地址」。不同书源的同名书视为不同书籍，可在书架同时存在。
删除书源不级联删除书籍与缓存；受影响书籍标记「书源已移除」。
删除书籍删除书架记录、阅读进度与章节记录；缓存文件按用户勾选决定是否删除。

5.4 网络、重试与并发

规则内容
超时搜索单源超时 15 秒；详情 / 目录 / 正文单次请求超时 20 秒。（具体数值可在设置中调整）
自动重试网络类失败自动重试 2 次，退避 1 秒、3 秒；解析为空、403、404 不自动重试。
并发上限搜索并发默认 5，下载并发默认 2；同一站点（同主机）同时请求不超过 2 个。
失败隔离任一请求失败只影响当前书源或当前章节，不阻塞其他任务。
离线检测发起请求前检测网络；离线时在线类操作直接给出离线提示，不进入超时等待。

5.5 本地数据与隐私

  • 所有书源、书籍、章节缓存、阅读进度保存在本机；不设账号，不上传任何数据。
  • 应用不内置、不推荐、不自动下载任何书源；书源来源与合法性由用户自行负责。
  • 请求头、Cookie 等敏感信息只用于当前请求，不写入日志；调试面板展示响应时截断并对用户自定义请求头做隐藏。
  • 日志仅记录错误类型与环节，不记录完整正文内容。

5.6 文案与反馈原则

错误提示必须说明“发生了什么 + 可能原因 + 可执行动作”三要素。例如不使用“加载失败”，而使用“目录解析为空，可能该书源目录规则已失效；可切换书源或到书源管理检查规则”。

06待确认问题

以下问题不阻塞 PRD 评审，但会影响实现范围或体验，需在开发前给出结论。

  1. TXT 单文件大小上限：是否需要支持 100MB 以上的超大合集？影响解析方式（内存解析 / 流式解析）与进度提示设计。
  2. 单章正文长度上限：用于防御异常规则抓到整页内容，暂以 [TBD] 占位。
  3. 是否需要在 P0 支持 JS 规则书源：Legado 生态中部分书源依赖 JS。若必须支持，规则引擎复杂度与安全风险（脚本执行）都会显著上升，需要单独评估。
  4. Windows 之外的打包目标：当前按 Win / macOS / Linux 设计，但首版是否只交付 Windows 安装包待定。
  5. 书源推荐关键词：校验书源时使用的默认测试词是固定值还是由用户配置，待定。
  6. 数据备份是否提前到 P0：涉及用户书源与进度的迁移成本，若首版就要给他人使用，建议提前。
评审通过后的下一步：进入技术方案与架构设计（模块划分、规则引擎设计、数据表结构、打包方式），再进入迭代开发。PRD 本身不包含技术实现细节。
